Дата: 2026-09-13. Статус: **предложено для визуального согласования**. UI kit сохранён в документации; стили рабочего Angular-приложения не изменены.

- [Референс пользователя](assets/visual-reference.png) — исходное изображение без обработки.

## 1. Основание и границы

Источник направления — чат «Варианты визуального оформления». Пользователь выбрал третий вариант из **последней** серии и подтвердил направление: cyberpunk, меньше деталей, больше лёгкости, воздуха и прозрачности; без пузырей, сфер, орбит и перегруженных сцен.

После просмотра v0.1 пользователь указал на несоответствие референсу и приложил исходное изображение. v0.1 отклонена: почти чёрные непрозрачные панели и бирюзовые кнопки не передавали его материалы и свет. v0.2 переработана непосредственно по изображению, сохранённому в `assets/visual-reference.png`. Точные параметры этой реализации остаются предложением для визуального согласования.

Рабочее название направления: **Indigo Glass**. Основа — насыщенное индиго, лавандовое освещение, розовые отражения и полупрозрачное стекло. Глубина возникает из просвечивающего фона и световых границ; одинаковые непрозрачные серые прямоугольники этому направлению не соответствуют. Финансовые данные остаются главным содержимым рабочего экрана.

UI kit задаёт оформление существующих сценариев. Не добавляет регистрацию, email-вход, роли, реальные платежи, новый Dashboard или новые API. Login содержит только пароль приложения. «Перевод» означает учёт перемещения между кошельками, а не отправку банковского платежа.

## 2. Визуальные правила

1. Фон цветной, сине-фиолетовый, с широкими переходами света. Не заменять его почти чёрным графитом. На рабочем экране яркие отражения остаются вне плотных данных.
2. Стеклянная поверхность пропускает цвет и размытые световые переходы сцены. Базовая непрозрачность — 56%, размытие — 24 px; под плотными данными применяется индиго-слой 86%. Поля имеют собственное локальное затемнение.
3. Один слой стекла. Не вкладывать несколько размытых полупрозрачных панелей друг в друга.
4. Световой край лавандово-розовый и тонкий; верхняя граница светлее боковых. Мягкий glow допустим у кнопки и одного края карточки. Текст и суммы не светятся.
5. Для Login фон — сохранённый референс с архитектурой, горизонтом и отражениями. В витрине он также служит подложкой сравнения формы и карточки. Рабочие таблицы используют спокойный индиго-фон без городского арта; без сфер, частиц, мелких сеток и непрерывной анимации.
6. Скругления умеренные. Основные кнопки прямоугольные со скруглением, не капсулы. Капсулы допустимы у коротких статусов.
7. На экране один основной призыв к действию. Остальные действия имеют меньший визуальный вес.
8. Цвет не заменяет текст: «Основной», «Архивный», «Расход», «Ошибка» обозначаются словами.

Арт возможен на Login и в пустых состояниях. В таблицах, формах и истории операций декоративных иллюстраций нет. Витрина использует локальный `assets/visual-reference.png` и CSS; новых изображений не генерировали. Сохранённый файл нужен также как постоянный эталон для сравнения следующих изменений.

### Типографика

Стек v0.2: `"Segoe UI", system-ui, -apple-system, sans-serif`. Он не требует загрузки внешних шрифтов и поддерживает кириллицу. Точное начертание может отличаться между ОС; отдельный брендовый шрифт — будущий выбор.

| Роль | Размер / строка | Насыщенность |
|---|---|---|
| Крупный баланс | 40 / 48 px | 400 |
| Заголовок страницы | 28 / 36 px | 400 |
| Заголовок секции | 22 / 30 px | 500 |
| Основной текст, поле, кнопка | 16 / 24 px | 400; кнопка 500 |
| Подпись и таблица | 14 / 20 px | 400 |
| Короткий badge | 12 / 16 px | 500 |

Основной текст не писать капсом. Суммы — `font-variant-numeric: tabular-nums`. Выравнивать суммы вправо в таблицах; валюту показывать явно. Длинные значения допускают перенос и адаптивное уменьшение размера без округления или обрезки значащих цифр.

### Геометрия и эффекты

| Параметр | Значения |
|---|---|
| Отступы | 4, 8, 12, 16, 24, 32, 48, 64 px |
| Радиусы | 10 px — поля/кнопки; 18 px — карточки; 24 px — крупная сцена/модальное окно |
| Контуры | 1 px; focus 2 px с отступом 3 px |
| Высота основного управления | минимум 44 px; многострочная кнопка может расти |
| Табличная строка | минимум 56 px |
| Внутренний отступ карточки | 28 px desktop, 22 px mobile; форма входа 36 / 24 px |
| Размытие стекла | 24 px; fallback — непрозрачный `--lw-surface` |
| Тень панели | `0 20px 60px rgba(13,16,53,.20)` + внутренняя верхняя световая линия |
| Glow акцента | `0 0 24px rgba(211,183,255,.20)` + слабое розовое отражение |
| Переход цвета/границы | 140 ms ease-out |
| Появление overlay | 180 ms ease-out; без движения больших областей |

При `prefers-reduced-motion` отключить декоративные переходы и анимации. Для режима без прозрачности использовать непрозрачные поверхности; читаемость не зависит от поддержки backdrop-filter.

## 4. Компоновка и адаптация

- Desktop от 1100 px: sidebar 224 px, верхняя строка 64 px, контент до 1280 px, внешние поля 32 px.
- Tablet 768–1099 px: верхняя навигация с кнопкой открытия меню, поля 24 px. Не превращать sidebar в набор иконок без подписей.
- Mobile до 767 px: одна колонка, поля 16 px, меню по кнопке. Действия могут переноситься на новую строку.
- Карточки: сетка по доступной ширине, минимум 260 px на карточку; на узком экране одна колонка.
- Таблицы прокручиваются горизонтально внутри подписанной области, а не всей страницы. Сумма и валюта доступны полностью. Допустим отдельный мобильный вид списка при сохранении всех важных данных.
- Проверить 360, 768 и 1440 px, масштаб текста/страницы 200%, длинные русские подписи и большие суммы.

Sidebar — предложение компоновки для будущего редизайна. Текущая навигация находится в header. Существующие маршруты сохраняются: кошельки, операции, переводы, история баланса, курсы валют, отчёт, справочники, аудит.

## 5. Компоненты и состояния

### Кнопки и ссылки

| Вариант | Вид | Использование |
|---|---|---|
| Primary | Лавандово-розовый градиент, тёмный текст | «Создать кошелёк», «Сохранить», «Войти» |
| Secondary | Полупрозрачная индиго-заливка, лавандовый контур | «Отмена», «Обновить» |
| Ghost | Без постоянного контура | Второстепенное действие в строке |
| Danger | Розовый текст и контур, тёмная заливка | Подтверждение удаления |
| Icon-only | Область 44×44 px | Только узнаваемое действие с доступным именем |

Default → hover: изменение заливки/границы. Pressed: более тёмная заливка без скачка размера. Focus: отдельное кольцо, не замена hover. Disabled: приглушённое оформление без hover; причина недоступности указана рядом, если не очевидна. Loading: «Сохранение…», ширина не скачет, повторный запрос блокируется, состояние объявляется вспомогательным технологиям. Ссылка имеет подчёркивание, если без него её можно спутать с текстом.

### Поля, select, checkbox, radio

- Постоянная подпись над полем; placeholder не заменяет label.
- Высота input/select 48 px, горизонтальные отступы 14 px. Textarea растёт по содержимому.
- Helper под полем; ошибка заменяет или дополняет helper, но не скрывает введённое значение.
- Состояния: default, hover, focus, filled, invalid, disabled, read-only. Read-only остаётся читаемым и допускает копирование.
- Валидация после взаимодействия с полем или отправки формы. Ошибка — текст рядом с полем + контур danger, связь через `aria-describedby`, `aria-invalid`.
- Сумма и валюта показаны рядом. Формат не меняет финансовую точность существующей модели; не приводить денежные строки к JavaScript Number ради форматирования.
- Использовать нативный select как начальный вариант. Поиск в большом справочнике добавляется при подтверждённой необходимости, с полноценным управлением клавиатурой.
- Checkbox/radio: видимая подпись кликабельна, общая область не меньше 44 px; выбранное состояние обозначается маркером, а не только цветом.

### Карточка кошелька

Порядок: имя → валюта и статус → баланс → действия. Статусы «Основной» и «Архивный» — короткие бейджи. Не окрашивать всю карточку под валюту. Пользовательский цвет кошелька — небольшой маркер, не замена семантическим цветам дохода/ошибки.

Состояния: обычная, выбранная, архивная, загрузка, ошибка загрузки. Выбранная карточка получает контур и текстовый/доступный признак выбора. Архивная остаётся читаемой. Не делать всю карточку кликабельной при вложенных кнопках; использовать явную ссылку или действие.

### Навигация и topbar

Активный раздел: мягкая лавандовая заливка + маркер + `aria-current="page"`. В topbar — название раздела, контекст и действия; не добавлять уведомления, аватары и поиск без соответствующих функций. «Выйти» доступно в навигации. Mobile-меню возвращает фокус на открывшую его кнопку после закрытия.

### Таблица / строка списка

Спокойная индиго-поверхность с непрозрачностью 86% на контролируемом фоне, тонкие горизонтальные разделители, без вертикальной сетки и декоративных полос. Текст слева, даты единообразно, деньги справа. Доход: знак «+» и подпись; расход: «−» и подпись. Перевод — отдельный тип с кошельком-источником и получателем, не просто зелёная/красная операция.

Состояния: default, hover при наличии действий, selected только при существующем выборе, loading, empty, error. Не показывать сортировку там, где она не реализована. Сохранить текущую курсорную пагинацию: «Показать ещё»/переходы, поддержанные API; не рисовать фиктивное количество страниц.

### Tabs

Текстовые вкладки с подчёркиванием активной. Для переключения панели — роли tablist/tab/tabpanel, управление стрелками и видимый focus. Для переходов по маршрутам — обычные ссылки навигации. Не смешивать эти два поведения.

### Modal / панель формы

Короткое подтверждение — dialog шириной до 440 px. Простая форма — до 560 px. Длинная форма создания кошелька может занимать широкую панель или страницу; выбор места требует отдельного экранного макета.

Заголовок, содержимое, действия внизу; явная «Отмена». Ограничение высоты по viewport, прокручиваемое содержимое. Клавиатурный фокус внутри, Escape закрывает с учётом несохранённых изменений, после закрытия фокус возвращается инициатору. Удаление показывает имя объекта и конкретное последствие согласно действующим правилам; не обещать откат, если его нет.

### Badge / chip

Badge сообщает статус и не выглядит кнопкой. Chip фильтра имеет удаление только если фильтр можно снять. Текстовые статусы: «Основной», «Архивный», «Доход», «Расход». Не заполнять строку множеством декоративных меток.

### Графики

Линия 2 px, основной ряд лавандовый, дополнительный розовый; знаки/тип линии и легенда различают ряды без опоры только на цвет. Без свечения и 3D. Сетка редкая, горизонтальная. У каждого графика период, валюта, подписи и доступная таблица исходных значений. Разные валюты не складывать без существующей конвертации и явного указания валюты отчёта.

График в витрине иллюстрирует стиль на вымышленных данных и не добавляет графический компонент в Angular.

### Empty, loading, error, feedback

| Состояние | Содержание |
|---|---|
| Пустой список | «Кошельков пока нет» + «Создайте первый кошелёк, чтобы начать учёт» + действие |
| Пустой фильтр | «По этим условиям ничего не найдено» + «Сбросить фильтры» |
| Загрузка | Статический skeleton по форме содержимого и доступная подпись «Загрузка…» |
| Ошибка | «Не удалось загрузить операции» + «Повторить»; введённые данные сохраняются |
| Успех | Короткое подтверждение, например «Кошелёк сохранён» |
| Потеря соединения | Постоянный баннер с состоянием; не обещать офлайн-сохранение |

Toast успеха может исчезнуть через 6 секунд; важная ошибка остаётся до закрытия/устранения. Toast не является единственным местом сообщения об ошибке формы. Не заменять неизвестное значение баланса нулём во время загрузки или ошибки.

## 6. Последовательность экранных макетов

1. Login: пароль, состояние входа, ошибка. Спокойный фон, одна стеклянная карточка.
2. Wallets: навигация, карточки/список, основной кошелёк, создание, пустое состояние.
3. Operations: фильтры, список, создание/редактирование операции.
4. Transfers: источник, получатель, суммы/валюты по текущему контракту, подтверждение.
5. Создание/редактирование кошелька, затем история баланса, курсы, отчёт, справочники и аудит.

«Dashboard» в предыдущем обсуждении — возможный экранный концепт, а не утверждённый новый маршрут. Макеты опираются на существующие требования и OpenAPI.

## 7. Как внедрять после согласования

1. Сравнить форму и карточку с сохранённым референсом: оттенок индиго, пропускание света, розово-лавандовые края, мягкие отражения, читаемость. Согласовать v0.2 по этому сравнению; не считать прежнее подтверждение направления одобрением новых параметров.
2. Перенести принятые токены в общий стиль Angular без параллельных конкурирующих палитр.
3. Собрать переиспользуемые элементы в `frontend/src/app/shared/ui/`; HTTP-клиенты и модели API не затрагивать.
4. Применить к Login и Wallets, затем к остальным экранам. Не менять бизнес-логику одновременно с оформлением.
5. Проверить состояния, клавиатуру, фокус, контраст на стекле, масштабы и размеры экрана; выполнить frontend-сборку и подходящие существующие тесты.

Витрина — демонстрационный документ. Её кнопки работают только локально с образцами; она не подключается к API, не сохраняет реальные данные и не является готовой библиотекой Angular-компонентов.

## 8. Проверка готовности UI kit

- Определены палитра, типографика, размеры, эффекты, адаптация и правила финансовых данных.

Подложка Login использует оригинал как CSS background, без редактирования исходного файла. Обрезка по размеру контейнера адаптивная; рядом доступна ссылка на полное изображение. Изображение не является заменой стилям компонентов: отдельная секция кнопок/полей и таблицы показывает те же материалы на CSS-фоне.

Стекло проверяется на фактическом фоне, а не на произвольном белом: при недостаточном контрасте усилить **локальный** индиго-слой под текстом. Не исправлять контраст превращением всего приложения в чёрную непрозрачную поверхность.
