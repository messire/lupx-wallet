# Конвенция: frontend

Короткая справка по размещению файлов внутри `frontend/src/app/`. Полный шаблон и обоснование — [ADR-0012 §3](../architecture/adr/0012-repository-structure-and-conventions.md#3-frontend-экраны-отдельно-от-доступа-к-данным).

## Куда положить файл

| Назначение | Расположение |
|---|---|
| HTTP-клиент и модели ответа API по предметной области | `data-access/<domain>/<domain>-api.service.ts`, `<domain>-api.models.ts` |
| Компонент, открываемый по маршруту | `features/<domain>/pages/<name>-page/` |
| Вложенный компонент конкретной feature (форма, виджет) | `features/<domain>/components/<name>/` |
| Модели состояния экрана (не модели API) | остаются в своей `features/<domain>/` |
| Авторизация, общая HTTP-инфраструктура (interceptor) | `core/` |
| Переиспользуемые элементы без привязки к экрану (UI, Money, пагинация) | `shared/` |
| Каркас приложения (шапка, меню, layout) | `layout/` |

## Правила

- Feature не импортирует другую feature напрямую. Общие зависимости — через `data-access`, `core`, `shared`; эти каталоги не зависят от features. Граф зависимостей — без циклов.
- Экрану нужны данные из другой предметной области (например форма операции получает список кошельков) — импортировать из `data-access/<другая-область>`, не из чужой `features/`.
- Компонент, шаблон, стили и тест (`*.spec.ts`) лежат рядом.
- HTTP-сервис называть явно: `*-api.service.ts` (не просто `*.service.ts` — конвенция явно требует указывать, что это HTTP-клиент). Страничный компонент — `*-page.component.ts`.
- kebab-case для файлов и папок.
- Не создавать неопределённые папки `Helpers`/`Utils`/`Common` — предметные имена.
- Doc-комментарии (JSDoc) — см. [repository-structure.md](repository-structure.md).
