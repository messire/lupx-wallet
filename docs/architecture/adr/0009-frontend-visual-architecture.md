# ADR-0009: Визуальная архитектура фронтенда — UI kit v0.3

## Статус

Принято — 2026-09-13 (v0.2), уточнено 2026-09-14 (v0.3). Пересобрано 2026-09-30. Дополнено 2026-11-14 (§6–§8: собственные выпадающие элементы, «+ добавить новый», без дублирующих кнопок).

**Состояние реализации:** общие токены и компоненты v0.3 — во всём приложении; перепланировка экранов под макеты v0.3 выполнена для Кошельков (включая форму), Операций, Переводов, Истории баланса и Курсов валют. Отчёт, Справочники, Аудит и Login остаются на общих токенах без перепланировки. §6–§8 внедрены во всех экранах (2026-11-14).

## Контекст

Фронтенд начинался со светлой сине-белой темы, заданной без согласования визуального направления. Пользователь инициировал пересмотр и выбрал направление: cyberpunk-эстетика, меньше деталей, больше воздуха и прозрачности, без пузырей, сфер и перегруженных сцен.

- **v0.1** отклонена: почти чёрные непрозрачные панели и бирюзовые кнопки не передавали материалы и свет референса.
- **v0.2 «Indigo Glass»** переработана по изображению пользователя (`docs/design/assets/visual-reference.png`): насыщенное индиго, лавандовое освещение, розовые отражения, полупрозрачное стекло. Утверждена 2026-09-13 после живого просмотра витрины.
- **v0.3** — уточнение по прямой корректировке пользователя 2026-09-14: убрано декоративное свечение, ослаблены границы и отражения; палитра, типографика и назначение компонентов сохранены. Эталон — [ui-kit.md](../../design/ui-kit.md), автономные экраны в `docs/design/`.

## Решение

1. **UI kit v0.3** (`docs/design/ui-kit.md`, токены `docs/design/tokens.css`) — единственная визуальная архитектура Angular-фронтенда.
2. `frontend/src/styles.scss` с токенами `--lw-*` — источник истины для цвета, радиуса, типографики и эффектов в приложении. Прежние токены `--color-*`/`--radius-*` удалены.
3. Переиспользуемые компоненты — в `frontend/src/app/shared/ui/` (Button, Field, Checkbox, Radio, Badge, Card, Tabs, Dialog, EmptyState, LoadingState, ErrorState, Skeleton, Toast): standalone, OnPush, только `var(--lw-*)`, без знания о доменных моделях.
4. Индиго-фон с широкими переходами света; стеклянные панели с просвечиванием фона, один слой стекла без вложенных размытий; лавандово-розовый градиент для основного действия; системный стек шрифтов (`"Segoe UI", system-ui, -apple-system, sans-serif`) без внешних загрузок.
5. Навигация — sidebar 224px от 1100px, ниже — кнопка «Меню» с выпадающей панелью.
6. **Выпадающие элементы — свои, а не браузерные** (решение пользователя 2026-11-14: «интерфейс имеет один стиль, а выпадающее меню — другой… всё должно быть в одном стиле»). Открытый нативный `<select>` и календарь `<input type="date">` рисует операционная система (на Windows — серое системное окно поверх индиго-интерфейса), CSS их не достаёт. Поэтому:
   - `app-select` (`shared/ui/select/`) заменяет `<select>` во всех формах и фильтрах: триггер — `<button role="combobox">` с видом поля (`.app-field__input`, стрелка 12 px / 16 px / 44 px как раньше), список — `role="listbox"`, фокус остаётся на триггере, активная строка — через `aria-activedescendant`; клавиатура — как у нативного select (стрелки, Home/End, Enter/Space, Escape/Tab, набор букв). Варианты объявляются `<app-select-option [value] [label]>`.
   - `app-date-input` (`shared/ui/date-input/`) заменяет `<input type="date">`: текстовое поле `дд.мм.гггг` (принимает и `гггг-мм-дд`) и кнопка календаря; сетка месяца с понедельника, стрелки/Home/End/PageUp/PageDown, Enter, Escape. Значение — по-прежнему строка API `yyyy-MM-dd` (или `''`), поэтому формы и валидаторы диапазонов не менялись; нераспознанный текст делает поле невалидным (`dateFormat`). `min`/`max` только блокируют дни календаря — сообщения о диапазоне остаются в формах.
   - Всплывающая панель всех трёх элементов (`app-select`, `app-date-input`, `app-currency-select`) — общая `AnchoredPanelDirective` (`shared/ui/popover/`): Popover API (top layer) + `position: fixed` по координатам поля, разворот вверх при нехватке места снизу. Абсолютная панель обрезалась прокручиваемым телом диалога и уходила под соседние карточки (`app-card` — свой контекст наложения). Оформление панели и строк — глобальные `.app-anchored-panel`/`.app-listbox` в `styles.scss`.
   - Числовое поле — без системных стрелок-счётчиков.
7. **«+ добавить новый» в выпадающих списках справочников** (решение пользователя 2026-11-14). Последняя строка списка, значение которого берётся из пользовательского справочника, — действие «+ добавить новый»: открывается диалог с обязательными полями записи, после создания запись сразу выбрана в поле. Сейчас это: тип кошелька (формы создания и изменения кошелька; поле — название), тип операции (форма операции; название и вид поведения, без «Перевод»), активная валюта в «Сменить валюту» (выбор из доступных, ещё не активных). Прежняя строка быстрого добавления типа под полем кошелька убрана. Не относится к фильтрам (там выбирают из существующего), к выбору кошелька (кошелёк — не справочник; создаётся полной формой), к валюте при создании кошелька (список доступных приходит из сервиса курсов, сервер сам активирует валюту) и к виду поведения (системный список).
8. **Одно действие — одна кнопка на экране** (решение пользователя 2026-11-14). Пустое состояние не повторяет действие, уже доступное в заголовке страницы или в панели фильтров («Добавить кошелек/операцию/перевод», «Сбросить фильтры», «Обновить сейчас»); вместо кнопки — текст, указывающий на неё. Кнопка восстановления после ошибки («Повторить») остаётся рядом с сообщением об ошибке.

### Что не входит

Изменение бизнес-логики, HTTP-клиентов, маршрутов и API; новые экраны, роли, регистрация, email-вход, реальные платежи. Login содержит только пароль приложения; «Перевод» — учёт перемещения между кошельками.

## Последствия

- Контраст текста на полупрозрачных поверхностях проверяется по месту на реальном фоне каждого экрана (4.5:1 для текста, 3:1 для границ и focus); наличие токенов само по себе этого не гарантирует.
- Дальнейшие визуальные изменения требуют либо новой итерации согласования с пользователем, либо изменения этого ADR.
- Выпадающие элементы теперь наши: доступность (роли, клавиатура, объявления) поддерживаем сами и проверяем тестами компонентов; поведение «как у системы» на мобильных (нативное колесо выбора) не используется.
- Классы багов, связанные с рендерингом (`<dialog>` без `[open]`, `box-sizing`), не ловятся jsdom-тестами и проверяются только в реальном браузере — см. `docs/PROGRESS.md`.

## Отклонённые варианты

- **v0.1** — не соответствовала референсу.
- **Сохранение alias-слоя `--color-*`/`--radius-*`** — был временным на период миграции экранов, удалён.
- **Оставить нативные `<select>`/`<input type="date">` и только перекрасить** (`color-scheme`, цвета `option`) — открытый список и календарь всё равно рисует система, на Windows результат на скриншотах пользователя оставался серым; единого стиля так не достичь.
- **`appearance: base-select` (стилизуемый select)** — пока только Chromium; в Firefox/Safari вернулся бы системный список, а для даты аналога нет.
- **Поиск в каждом выпадающем списке** — не требовался; комбобокс с поиском остаётся только у валют (150+ значений).
- **Новый набор SVG-иконок и «контекстная» подпись в topbar из макета** — не перенесены: оформление без источника данных.
