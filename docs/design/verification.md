Дата: 2026-09-14. Объект проверки — автономные `wallets.html`, `wallet-form.html`, `operations.html` и `preview.html`, не Angular-приложение. Среда — браузер Codex, локальная выдача через `serve.mjs`.

## Полная форма и Operations — расширение v0.3

| Проверка | Результат |
|---|---|
| 1440 / 768 / 360 px | Обе страницы проверены; ширина документа не превышает viewport. Таблица Operations прокручивается в своей области. Исправлено переполнение от скрытой подписи столбца действий. |
| Создание кошелька | Пустая отправка показывает ошибки названия и типа, фокус на названии. Выбор значения очищает ошибку. |
| Точность и ошибка сохранения | `1234567890.123456789` остаётся без изменения после ошибки; повторная отправка во время ожидания заблокирована. Успешное сохранение показывает локальное подтверждение. |
| Редактирование основного | Учёт в общей сумме включён и заблокирован; валюта только для чтения. |
| Справочники | Проверка статического макета (быстрое добавление валюты в форме кошелька) устарела: в приложении валюта выбирается из доступных (`GET /currencies/available`), быстрого добавления нет. В статическом макете повтор после ошибки загрузки возвращал фокус на тип; в приложении такого возврата **нет** (у «Повторить» типа кошелька фокус не переносится — manual verify/TODO). Вкладка «Валюты» (добавление из доступных, «Убрать из активных» с подтверждением, пустое состояние) покрыта тестами компонента; проверка в браузере (1440 / 768 / 360 px, клавиатура в комбобоксе) — вручную, не выполнена. |
| Валюты: фокус и подсказки | Покрыто тестами компонентов (jsdom), в браузере — manual verify. Форма кошелька: «Повторить» при ошибке загрузки доступных возвращает фокус на комбобокс (список не раскрывается); подсказка о незагруженном списке — одна, под полем, через `aria-describedby`; подпись поля не ссылается на отсутствующий элемент. Вкладка «Валюты»: после успешного «Убрать из активных» фокус переходит на вкладку «Валюты» (кнопка строки исчезает вместе со строкой), после неуспешного — остаётся на кнопке; «Повторить» при ошибке списка доступных переносит фокус на панель вкладки; «Все доступные валюты уже добавлены» — постоянная подсказка под полем; после добавления — тост «Валюта добавлена; курсы и история загружаются в фоне»; после 409 при добавлении оба списка перечитываются, выбранный код сбрасывается; сбой `/currencies/available` не блокирует остальные вкладки. Комбобокс: закрытие и «тронуто» при уходе фокуса, повторный клик открывает список, Home/End. |
| Отчёт: сумма на дату | Для исторической суммы всегда показано «Курс по состоянию на <дата>» (UC-21), при исключённых кошельках рядом с бейджем — «Сумма неполная: история курсов ещё загружается, повторите позже»; причина исключения выводится как пришла с backend. Проверено тестами компонента; в браузере — manual verify. |
| Отмена изменений | У изменённой формы кошелька и операции есть подтверждение; «Продолжить заполнение» сохраняет ввод. |
| Фильтры Operations | Расходы возвращают три строки; обратный диапазон дат показывает ошибку. «Загрузить ещё» увеличивает список с 6 до 8 строк. |
| Состояния Operations | Пустое, загрузка с `aria-busy`, ошибка и повтор проверены. Длинная сумма `+1 234 567 890,123456789 EUR` не округляется и не распирает документ на 360 px. |
| Правила действий | У части перевода нет отдельного изменения/удаления. Удаление доступно для любой даты (мягкое, ADR-0002 §3): строка остаётся серой и перечёркнутой с бейджем «Удалена», «Восстановить» без подтверждения, «Изменить»/«Удалить» скрыты. *Статичный макет `operations.html` этих состояний не содержит (устарел); проверка — в Angular-приложении (manual verify: визуальный вид строки, контраст).* |
| Форма операции | Отрицательный расход, в том числе с пробелом перед минусом, отклоняется. Корректировка допускает отрицательное значение и предлагает только «Изменение на сумму (+/−)» (отправляется как `Delta`; способа «Новое значение баланса» нет — баланс на дату задаёт отдельная форма «Указать баланс»). Проверены создание и повторное открытие на редактирование. |
| Ошибка операции | Значение сохраняется после ошибки; поля и повторная отправка блокируются при ожидании. Мобильный диалог помещается по ширине и прокручивается по высоте. |
| Системная строка и «Указать баланс» | Рендер строки, ссылка «История изменений», форма, живая подсказка «По операциям на конец дня» (запросы, вычитание корректирующей суммы дня, отмена устаревших ответов, ошибка), префилл прежнего значения, тосты 201/200/«совпадает с операциями», ошибки 400/404/409 и блокировка закрытия на время запроса покрыты тестами компонентов (jsdom). В браузере — manual verify: вид курсива и бейджей на стекле, forced-colors, длинные названия бейджей на 360 px, возврат фокуса на «Указать баланс»; **live-область** (`aria-live="polite"`) — объявление скринридером (NVDA/VoiceOver) «Считаем баланс по операциям…» → «По операциям на конец дня: N» при смене даты и кошелька, без дублей и без прерывания ввода; подстановка прежнего значения и строка «На эту дату баланс уже указан» читаются один раз. |
| Меню на 360 px | Escape закрывает меню и возвращает фокус на кнопку. |
| Консоль | В проверенных вкладках ошибок JavaScript не обнаружено. |

## Границы проверки

Уточнение select: в макетах и витрине добавлен общий `select.css`. В браузере проверены выбор «Накопления», `padding-right: 44px` и положение стрелки в 16 px от правого края. Предыдущие снимки полного экрана показывают состояние до этой точечной правки.

- Масштаб браузера 200%, screen reader, другие браузеры и режимы reduced-transparency / forced-colors ещё не проверены. CSS-fallback предусмотрен, но это не доказательство прохождения проверки на всех платформах.
- Полный аудит контраста прозрачных поверхностей не выполнен. Сохранённые цвета и отдельные контрольные пары не заменяют измерение каждого состояния на реальном фоне.
- Макет не обращается к API. Создание, редактирование, выход и реальные финансовые операции здесь не выполняются. Эти сценарии нужно проверять отдельно при переносе в Angular.
- Растровый ориентир не позволяет гарантировать точные размеры и цвета. Для реализации используются общие токены и CSS; это техническая фиксация выбранного направления, а не заявление о побайтовом совпадении с генерацией.
- Новый HTML ещё не проходил отдельную пользовательскую приёмку. Проверки этой страницы не означают готовность приложения к релизу.
