# Глоссарий терминов

Источник: [wallet_business_prompt_ru_v2.md](./wallet_business_prompt_ru_v2.md). Технические идентификаторы (English identifiers) приведены в скобках для использования в дальнейшем проектировании; определения — на русском языке, строго на основе текста бизнес-требований, без домысливания.

| Термин (English identifier) | Определение |
|---|---|
| **Wallet** (кошелек) | Именованное место хранения денег пользователя в определенной валюте. Имеет название, валюту, тип, назначение/описание, начальный баланс, дату начала учета, признак включения в общую сумму, признак основного кошелька, статус архивирования, ручной порядок отображения, опциональные цвет и иконку. Решено (Q15, уточнено [ADR-0002](../architecture/adr/0002-record-lifecycle.md)): валюту кошелька можно изменить только пока по нему нет истории (**History**) — операций, включая мягко удаленные; слепки баланса при смене валюты перестраиваются. |
| **Wallet Type** (тип кошелька) | Классификатор кошелька, хранящийся как расширяемый справочник (не закрытый enum в коде); кошелек ссылается на него по идентификатору. |
| **Primary Wallet** (основной кошелек) | Один из кошельков пользователя, отмеченный как основной. В любой момент времени может быть выбран только один основной кошелек. Решено (Q7): наличие основного кошелька обязательно; архивирование текущего основного кошелька запрещено, пока пользователь не назначит другой кошелек основным. |
| **Primary Currency** (основная валюта отображения) | Валюта текущего основного кошелька. Используется как валюта отображения общей суммы. Отдельной настройки «валюта приложения» не существует — она полностью производна от основного кошелька. |
| **Include In Total flag** (признак включения в общую сумму) | Атрибут кошелька, определяющий, учитывается ли его баланс при расчете общей суммы по всем кошелькам. Решено (Q8): у основного кошелька этот признак всегда включен и не может быть выключен, пока кошелек остается основным. |
| **Archiving** (архивирование) | Механизм скрытия кошелька из активного использования без удаления истории операций. Заменяет собой удаление кошельков, имеющих историю (**History**) — то есть хотя бы одну операцию, включая мягко удаленные. Кошелек без операций удаляется окончательно вместе со своими слепками баланса (решено, Q2; [ADR-0002](../architecture/adr/0002-record-lifecycle.md)), а не архивируется. Архивный кошелек исключен из активных списков, но его история и слепки сохраняются, и он участвует в исторической общей сумме. Решено (Q16): архивирование не меняет автоматически признак «включен в общую сумму» — это независимые атрибуты. |
| **Manual Display Order** (ручной порядок отображения) | Порядок кошельков в списке, задаваемый пользователем вручную. |
| **Exchange Rate** (курс валюты) | Соотношение между двумя валютами, загружаемое из внешнего общедоступного бесплатного сервиса. Точность курса используется такой, какую предоставляет внешний сервис, без дополнительного округления. Решено (Q5): источник — сервис [Frankfurter](https://www.frankfurter.app/). Различаются **последний курс** (на момент последнего обновления; используется для текущей общей суммы) и **история курсов** (курсы по датам; используется для исторической общей суммы). Курсы существуют только для пар «активная валюта → основная валюта» ([ADR-0004](../architecture/adr/0004-currencies-and-exchange-rates.md), §4, §9); приложение читает их только из своей базы (§8), а историю заполняет заранее (см. **Historical Rate Backfill**). Для даты без курса (например, выходной) используется ближайший более ранний. Курсы удаляются вместе с валютой. |
| **Rate Auto Update** (автоматическое обновление курсов) | Периодическое обновление курсов валют. ⚠ Изменение исходного требования (Q5): периодичность изменена пользователем с «раз в 3 часа» (исходный текст раздела 2) на «раз в сутки» — см. раздел «Изменения исходных требований» в конце документа `user-scenarios.md`. |
| **Rate Manual Update** (ручное обновление курсов) | Обновление курсов валют по явному действию пользователя (кнопка); после него трехчасовой цикл автообновления запускается заново. |
| **Last Successful Rate** (последний успешно загруженный курс) | Курс, используемый системой, если очередная попытка загрузки новых курсов завершилась неудачей. |
| **Available Currency** (доступная валюта) | Валюта, которую отдает сервис курсов ([ADR-0004](../architecture/adr/0004-currencies-and-exchange-rates.md), §7). Список хранится в приложении и обновляется вместе с курсами; пользователь им не управляет. Названия английские, из сервиса. Нужен только для списков выбора: при создании кошелька и при добавлении валюты в активные. Криптовалют и произвольных кодов в нем нет. Если сервис перестал отдавать валюту, она исчезает из доступных, а активной остается. |
| **Active Currency** (активная валюта) | Валюта справочника пользователя — та, которую он использует. Пользователь добавляет ее из доступных или она становится активной автоматически при создании кошелька в этой валюте; убрать из активных можно только неиспользуемую валюту (**Reference Item Usage**). Состояния «деактивирована» у валюты нет: валюта либо активна, либо нет. Курсы загружаются только по активным валютам. Переход «добавлена в активные» запускает загрузку курсов и истории валюты. |
| **Historical Rate Backfill** (дозагрузка истории курсов) | Фоновая загрузка курсов активных валют к основной валюте за период от самой ранней даты начала учета (среди всех кошельков, включая архивные) до сегодняшнего дня. Запускается при добавлении валюты в активные, создании кошелька, смене основной валюты и по расписанию; прерванная загрузка продолжается с места остановки; историю ежедневно продлевают до сегодняшнего дня (выведено при реализации, [ADR-0004](../architecture/adr/0004-currencies-and-exchange-rates.md), §9). Пока дозагрузка не завершена, историческая общая сумма неполная: кошельки без курса исключаются из нее с указанием причины. |
| **Operation** (операция) | Единичная финансовая запись, изменяющая или фиксирующая состояние баланса кошелька. Ссылается на тип операции по идентификатору. Поддерживает редактирование; любое изменение фиксируется в аудите. Решено (Q14): сумма операции должна поддерживать произвольную точность (не только 2 знака после запятой), чтобы покрыть валюты вроде криптовалют с большим числом знаков после запятой. Удаляется только мягко (см. **Soft Delete**), с любой датой, и может быть восстановлена (см. [ADR-0002](../architecture/adr/0002-record-lifecycle.md)); мягко удаленную операцию редактировать нельзя. |
| **Soft Delete** (мягкое удаление) | Удаление операции или перевода без физического стирания записи ([ADR-0002](../architecture/adr/0002-record-lifecycle.md), §3; решение пользователя 2026-09-30). Допустимо с любой датой. Запись остается в списке и отображается серой, перечеркнутой красной линией; не участвует в расчете текущего баланса, слепков, общей суммы и корректирующих сумм; остается в **History** кошелька и считается **использованием** элемента справочника. Запускает каскадный пересчет слепков и фиксируется в аудите. Физического удаления операций нет. Перевод удаляется целиком, обе операции вместе; отдельную «ногу» перевода удалить нельзя. |
| **Restore** (восстановление) | Обратное действие к мягкому удалению: запись снова участвует в расчетах, слепки баланса пересчитываются от ее даты, действие фиксируется в аудите. Перевод восстанавливается целиком. Удаленную запись нельзя редактировать, пока она не восстановлена. |
| **History** (история кошелька) | Набор фактов, введенных пользователем по кошельку: только операции, включая мягко удаленные и обе «ноги» переводов. Слепки баланса, ненулевой начальный баланс и заявленные балансы историей не считаются — это данные, рассчитанные системой или введенные вместе с кошельком. Наличие истории запрещает окончательное удаление кошелька (только архивирование) и смену его валюты ([ADR-0002](../architecture/adr/0002-record-lifecycle.md), §1–§2). |
| **Reference Item Usage** (использование элемента справочника) | Наличие ссылок на элемент справочника от кошельков (включая архивные) и операций (включая мягко удаленные). Используемый элемент типа кошелька или типа операции нельзя удалить окончательно — только деактивировать; неиспользуемый удаляется окончательно. Используемую валюту нельзя убрать из активных (деактивации у валюты нет, [ADR-0004](../architecture/adr/0004-currencies-and-exchange-rates.md), §7); неиспользуемая убирается окончательно. Записи курсов валют использованием валюты не считаются и удаляются вместе с валютой ([ADR-0002](../architecture/adr/0002-record-lifecycle.md), §4). |
| **Operation Type** (тип операции) | Классификатор операции, хранящийся как расширяемый справочник. Ссылается на один из элементов справочника **OperationBehaviorKind** (доход/расход/перевод/корректировка) — этой ссылкой определяется базовое поведение. Пользователь может добавлять новые типы, если их поведение укладывается в уже поддерживаемое (например, «зарплата», «продукты», «кэшбэк» — все ссылаются на базовое поведение доход/расход). Решено (Q1): тип операции фактически выполняет роль категории, но на первом этапе по типам операций не строится аналитика/отчетность. |
| **Income** (доход) | Один из четырех базовых видов операции: увеличивает баланс кошелька. |
| **Expense** (расход) | Один из четырех базовых видов операции: уменьшает баланс кошелька. |
| **Transfer** (перевод) | Один из четырех базовых видов операции: перемещение денег между двумя кошельками пользователя. Разрешен только между кошельками с одинаковой валютой. Представлен двумя связанными операциями (списание и зачисление), обрабатываемыми как единое действие: перевод создается, мягко удаляется и восстанавливается целиком, обе операции вместе. Решено (Q9): конвертация валют при переводе не предусмотрена — перемещение между кошельками разных валют выполняется вручную как две несвязанные операции (расход + доход). Решено (Q10): комиссия за перевод между своими кошельками не поддерживается, сумма списания всегда равна сумме зачисления; пример типа операции «комиссия» из раздела 3 относится к обычному расходу (например, комиссия банка), не связанному с переводом. |
| **Manual Balance Adjustment** (ручная корректировка баланса) | Один из четырех базовых видов операции: ручное изменение баланса кошелька пользователем. Решено (Q3): пользователь при создании корректировки выбирает один из двух способов ввода — абсолютное новое значение баланса либо дельту изменения (+/-). |
| **Current Balance** (текущий баланс) | Актуальное значение остатка средств кошелька на настоящий момент. Мягко удаленные операции и переводы в нем не учитываются. |
| **Balance Snapshot** (слепок баланса / история баланса) | Запись исторического баланса кошелька на конкретную дату. Создается или обновляется ежедневно в 12:00 UTC; для одного кошелька и одной даты существует не более одной записи. Обновляется также при ручной корректировке или изменении данных, влияющих на баланс за эту дату (включая мягкое удаление и восстановление операции или перевода; мягко удаленные записи в слепок не входят). Слепок — данные, рассчитанные системой, а не история кошелька (см. **History**): удаляется вместе с кошельком и перестраивается при смене валюты кошелька. Решено (Q4): изменение, затрагивающее дату в прошлом, приводит к каскадному пересчету слепков за эту и все последующие даты (баланс накопительный). Решено (Q12): если плановый запуск в 12:00 UTC был пропущен (приложение не работало), пропущенные слепки досоздаются задним числом при следующем запуске. Решено (Q13): для дат раньше «даты начала учета» кошелька баланс считается равным 0. |
| **Total Amount** (общая сумма) | Сумма балансов всех кошельков с включенным признаком «включен в общую сумму», выраженная в основной валюте отображения (валюте текущего основного кошелька). |
| **Historical Total Amount** (историческая общая сумма) | Общая сумма на выбранную прошедшую дату, рассчитанная по слепкам баланса и выраженная в валюте текущего (а не исторического) основного кошелька, с использованием курса валюты, актуального на эту дату (или последнего известного курса до этой даты). Курсы читаются только из базы приложения; если для кошелька курса на дату нет (история еще загружается), кошелек исключается из суммы с указанием причины ([ADR-0004](../architecture/adr/0004-currencies-and-exchange-rates.md), §8, §9). |
| **Audit** / **Audit Entry** (аудит / запись аудита) | Механизм и записи, фиксирующие любые изменения финансовых данных: создание, редактирование, удаление или отмену (включая мягкое удаление и восстановление, физическое удаление, архивирование, деактивацию), ручные корректировки, создание и обновление слепков баланса, связанные изменения при переводах. Каждая запись аудита фиксирует: что изменилось, когда, какая запись затронута, значение до изменения, значение после изменения, и был ли автор изменения пользователем или системой. История аудита не должна теряться при последующих изменениях данных. |
| **Actor** (инициатор действия) | Кто выполнил действие, отраженное в аудите: **User** (пользователь) — ручное действие; **System** (система) — фоновый процесс приложения (например, ежедневное создание слепка баланса или автообновление курсов). |
| **Reference / Dictionary** (справочник) | Отдельно хранимый и редактируемый набор допустимых значений (например, типы кошельков, типы операций), на который бизнес-сущности ссылаются по идентификатору, а не как на жестко зашитый в код закрытый список (enum). Применяется к наборам значений, которые пользователь потенциально может расширять без появления новой бизнес-логики. Решено (Q11): элемент справочника, уже используемый существующими записями (см. **Reference Item Usage**), нельзя удалить — только деактивировать, по аналогии с архивированием кошельков (для валюты — иначе, см. **Active Currency**). |
| **Currency** (валюта) | Добавлено при проектировании DDD-модели как отдельный справочник пользователя (по аналогии с типами кошельков/операций): запись **Currency** — это **активная валюта** (код, название); набор кодов для выбора определяется списком **доступных валют** сервиса курсов, а не произвольным вводом (изменено [ADR-0004](../architecture/adr/0004-currencies-and-exchange-rates.md), §7; прежнее допущение «произвольные валюты, включая криптовалюты» утратило силу). Признака активности у записи нет — наличие записи и означает, что валюта активна. |
| **OperationBehaviorKind** (вид поведения операции) | Добавлено при проектировании DDD-модели: фиксированный набор из четырех базовых видов поведения операции — доход, расход, перевод, ручная корректировка (раздел 3 требований). Хранится как справочная таблица, а не закрытый enum в коде, но, в отличие от **Operation Type**, недоступен пользователю для редактирования — новое значение может появиться только вместе с обновлением приложения, так как требует новой логики обработки. Каждый **Operation Type** ссылается ровно на один `OperationBehaviorKind`. |
| **Accounting Start Date** (дата начала учета) | Дата, с которой ведется учет операций по конкретному кошельку; один из атрибутов кошелька. Баланс на даты раньше этой считается равным 0 (решено, Q13). |

## Термины, упомянутые, но не входящие в объем первого этапа

Перечислены для полноты глоссария и трассируемости к разделу 8 исходных требований — определения не разрабатываются на этом этапе:

- **Category** (категория) — как отдельная сущность не вводится: её роль на первом этапе выполняет **Operation Type** (решено, Q1). Из объема первого этапа исключена именно аналитика/отчетность по категориям-типам, а не сама возможность их создавать.
- **Budget** (бюджет)
- **Recurring Payment** (регулярный платеж)
- **Debt** (долг)
- **Credit Product** (кредитный продукт)
- **Bank Statement Import** (импорт банковских выписок)
- **Available Balance** (доступный баланс, в отличие от фактического) — упомянут как возможное будущее направление, которое не должно быть архитектурно заблокировано.
- **Credit Limit** (кредитный лимит) — аналогично.
