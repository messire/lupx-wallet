# ADR-0005: Произвольная точность хранения денежных сумм

## Статус

Принято

## Контекст

Исходные бизнес-требования не оговаривают точность хранения денежных сумм явно. Приложение однопользовательское, мультивалютное, и раздел 2 требований указывает, что «точность курса используется в том виде, в котором ее предоставляет внешний сервис» — то есть точность в системе не должна быть искусственно ограничена стандартными двумя знаками после запятой, характерными только для части фиатных валют. Это было зафиксировано как открытый вопрос Q14: нужна ли поддержка валют с нестандартной точностью (например, криптовалют с 8 знаками после запятой).

## Решение

Система должна поддерживать хранение сумм операций и балансов с произвольной точностью (решено, Q14), а не с фиксированной денежной точностью в 2 знака. Это относится как к суммам операций, так и к текущему балансу, слепкам истории баланса и курсам валют.

Конкретный тип данных на уровне PostgreSQL/EF Core (например, `numeric` без фиксированного масштаба, либо `numeric` с достаточно большим масштабом) — предмет проектирования схемы БД, не фиксируется этим ADR.

## Последствия

- Арифметика с суммами (пересчет по курсу, суммирование по кошелькам с разной точностью для общей суммы) должна выполняться без потери значащих разрядов; округление, если оно потребуется для отображения, выполняется только на уровне представления (UI), а не при хранении.
- Общая сумма и историческая общая сумма (см. **Total Amount**, **Historical Total Amount**) агрегируют суммы из кошельков с потенциально разной точностью — итоговое значение в валюте основного кошелька должно сохранять точность, достаточную для не потерять значащие разряды исходных валют до момента отображения.
- Курсы валют от Frankfurter (см. ADR-0001) в фиатных парах обычно имеют ограниченную точность; хранение с произвольной точностью не означает, что все значения фактически будут иметь много знаков — это лишь снимает искусственное ограничение для тех валют, где точность нужна.
- Выбор конкретного типа данных и стратегии округления при отображении остается открытым инженерным решением на этапе проектирования схемы БД и API-контрактов.

## Альтернативы

- **Фиксированная точность 2 знака для всех сумм** — отклонено пользователем (Q14): не покрывает случаи вроде криптовалют с 8 знаками после запятой.
