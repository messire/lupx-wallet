# ADR-0005: Денежные суммы — произвольная точность

## Статус

Принято (август 2026, Q14). Пересобрано 2026-09-30.

**Состояние реализации:** реализовано.

## Контекст

Исходные требования не оговаривают точность сумм, но раздел 2 требует использовать точность курса «в том виде, в котором её предоставляет внешний сервис». Фиксированные два знака после запятой характерны лишь для части валют. Открытый вопрос Q14 — нужна ли поддержка нестандартной точности — закрыт пользователем положительно.

## Решение

1. Суммы операций, балансы, слепки и курсы хранятся **без фиксированной точности**: в PostgreSQL — `numeric` без `precision`/`scale`; в C# — `decimal` внутри `Money` (`SharedKernel`).
2. Арифметика (суммирование по кошелькам, пересчёт по курсу) выполняется без потери значащих разрядов. Округление, если требуется, — только на уровне представления, не хранения.
3. В API (`docs/api/openapi.yaml`, схема `Money`) сумма передаётся **строкой** с точкой как десятичным разделителем, чтобы не терять точность в JSON-числах. Форматирование — с `CultureInfo.InvariantCulture`.
4. Frontend никогда не преобразует сумму в `number`: проверка формата, разбор ввода и форматирование для показа выполняются над строкой (`frontend/src/app/shared/money/money.ts`).
5. `Money` допускает арифметику только между значениями одной валюты; попытка смешать валюты — ошибка на уровне типа.

## Последствия

- Общая и историческая общая сумма агрегируют кошельки с разной точностью; итог хранит достаточно разрядов до момента отображения.
- Значения фактически имеют столько знаков, сколько нужно валюте; произвольная точность лишь снимает искусственный предел.
- `decimal` в .NET ограничен 28–29 значащими цифрами — практический, а не строгий предел «произвольности». Для поддерживаемых валют ([ADR-0004](./0004-currencies-and-exchange-rates.md)) этого достаточно.
- Исходное обоснование (криптовалюты с восемью знаками) утратило силу: список валют ограничен тем, что отдаёт Frankfurter, криптовалют в нём нет. Решение сохраняется как более простое и не мешающее.

## Отклонённые варианты

- **Фиксированная точность в два знака** — не покрывает валюты с большей точностью (Q14).
- **Число в JSON** — теряет точность при разборе в JavaScript.
