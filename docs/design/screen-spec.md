## Общая визуальная основа

Те же `tokens.css` и `wallets.css`, что у полного Wallets; `screens.css` задаёт только компоновку форм и списка. Исходные индиго, лаванда и мягкий розовый сохранены. Фон рабочий, без городской картинки. Панели имеют слабый край и тень; свечения нет. Primary — прежний пастельный градиент. Контуры полей и клавиатурного фокуса различимы, но не используются для декоративной обводки панелей.

Sidebar, отступы и типографика общие. На 768 px фильтры переходят в две колонки, на 360 px — в одну; навигация открывается по кнопке. Таблица прокручивается внутри подписанной области, а не вместе с документом. Форма операции ограничена размером viewport и прокручивается по высоте.

## Полная форма кошелька

Отдельная страница; ширина панели до 560 px. Название и поля идут одной колонкой, действия расположены внизу. При создании дополнительные настройки свёрнуты, при редактировании раскрыты.

| Поле | Создание | Редактирование |
|---|---|---|
| Название | Обязательно | Доступно |
| Тип кошелька | Обязательный справочник, быстрое добавление | Доступно |
| Валюта | Обязательный выбор из доступных валют сервиса курсов (поиск по коду и названию); быстрого добавления нет, валюта становится активной при создании кошелька | Только чтение; изменение — отдельный сценарий, только из активных |
| Начальный баланс | Обязательная строковая сумма, по умолчанию `0.00` | Только чтение |
| Дата начала учёта | Обязательная дата | Только чтение |
| Описание | Необязательно, в дополнительных настройках | Доступно |
| Учитывать в общей сумме | Флаг в дополнительных настройках | Основной кошелёк всегда включён, флаг заблокирован |
| Порядок отображения | Целое число, по умолчанию 0 | Доступно |
| Цвет, иконка | Необязательные значения существующего контракта | Доступно |

Пять обязательных полей соответствуют текущему сценарию создания. Дополнительные поля уже присутствуют в `CreateWalletRequest`, хотя текущая Angular-форма создания выводит не все из них; макет предлагает их размещение в раскрываемой секции. Новый API для этого не проектируется. Флаг назначения основным кошельком не добавлен: при создании первого кошелька это решает существующая логика.

Проверка обязательных полей происходит при выходе из поля/изменении и при отправке; первая ошибка получает фокус. Ошибка сохранения не очищает ввод. Ожидание блокирует поля и повторную отправку. Для ухода по ссылке с изменённой формой предусмотрено подтверждение. Обновление страницы не защищается и сбрасывает образец.

«Проверка макета» содержит режимы создания/редактирования/основного кошелька, обычное состояние, ошибки полей, загрузку/ошибку справочников, сохранение, ошибку/успех сохранения и длинные значения. Быстрое добавление типа действует только внутри этой формы; после обновления исчезает. Поле «Валюта» — комбобокс с поиском: подпись, `aria-describedby`, `aria-invalid` и `aria-required` приходят от обёртки поля, ручной `id` не нужен. Список закрывается при уходе фокуса (поле помечается тронутым, выбранное значение остаётся видимым); повторное нажатие на поле в фокусе открывает список; стрелки, Home/End, Enter и Escape работают с открытым списком. Сообщения «Список валют пуст» и «Ничего не найдено» — отдельная вежливая live-область, а не элемент списка. Если список доступных валют пуст (до первой загрузки курсов), под полем один раз показана подсказка «Список валют ещё не загружен из сервиса курсов. Обновите курсы на экране «Курсы валют» или повторите позже» (она связана с полем через `aria-describedby`; в самом списке — только «Список валют пуст»). Ошибка загрузки списка выводится ошибкой поля (`role="alert"`), поле остаётся на месте, рядом — «Повторить»; после нажатия фокус переходит на комбобокс (список при этом сам не раскрывается). После создания кошелька список доступных валют не перезапрашивается (он не меняется), перечитываются только активные. Успешное сохранение показывает подтверждение, но не меняет карточки на соседней странице.

## Операции

Заголовок и одно основное действие «Добавить операцию». Ниже спокойная панель фильтров: кошелёк, тип, начало и конец периода; «Применить» и «Сбросить». Обратный диапазон дат показывает ошибку. Пустой результат фильтра предлагает сброс, ошибка загрузки — повтор без очистки фильтров.

Таблица: дата, кошелёк, тип, сумма, режим корректировки, меню действий. Доход/расход имеют знак и текстовый тип, поэтому цвет не является единственным различием. Действия строки находятся под «···». «Загрузить ещё» показывает продолжение; фиктивных страниц и общего количества API-записей нет.

Форма создания/редактирования — диалог до 560 px:

- кошелёк, тип, сумма и дата обязательны;
- доход и расход требуют положительной суммы;
- корректировка раскрывает выбор «Изменение на сумму (+/−)» / «Новое значение баланса»; допускает отрицательные значения;
- тип Transfer не предлагается для прямого создания операции;
- суммы проверяются и сохраняются как строки, без преобразования через `Number`; ввод использует точку, отображение — запятую и группировку разрядов без округления;
- ошибка оставляет введённые значения; повторная отправка во время ожидания заблокирована;
- отмена и Escape учитывают несохранённые изменения.

Часть перевода открывает действие «Открыть перевод», а не отдельное редактирование/удаление. Действие открывает список переводов в `transfers.html`; привязка конкретной операции к строке перевода в автономном образце не моделируется. История изменений также пока не имеет отдельного макета. **Удаление и восстановление** ([ADR-0002](../architecture/adr/0002-record-lifecycle.md) §3, §5; вид удалённой строки — ADR-0002 §3): операцию можно удалить с любой датой — удаление мягкое, требует подтверждения с её данными и последствием («запись останется в списке, исключится из расчётов, баланс кошелька будет пересчитан, операцию можно восстановить»). Удалённая операция остаётся в списке всегда: серая, перечёркнутая красной линией строка (`.is-deleted`, см. ui-kit §5) с бейджем «Удалена» в ячейке даты (чтобы скринридер читал его до данных строки); в меню «···» у неё только «Восстановить» (без подтверждения, тост «Операция восстановлена», список перезагружается) и «История изменений», «Изменить»/«Удалить» скрыты. Часть перевода (в том числе удалённая) не имеет меню «···»: в строке видимая ссылка «Открыть перевод» на `/transfers`, доступная с клавиатуры; восстанавливается и удаляется только вместе с переводом на странице переводов. Ошибка удаления показывается внутри диалога подтверждения, ошибка восстановления — error-тостом (`role="alert"`); при конфликте 409 (запись изменена в другой вкладке) список перезагружается. Аналогично на экране «Переводы».

> **Устаревшая витрина.** Автономный макет `operations.html` ещё показывает прежнее правило («за прошлые даты удаление недоступно», полное удаление из памяти) и не моделирует удалённую строку; актуальное поведение — в Angular-реализации и в этом абзаце.

## Демонстрационные границы

Все кошельки в списке Operations — EUR. Для стабильной проверки задана дата **14.09.2026** и начало учёта **01.09.2026**. При переносе брать текущую дату и период конкретного кошелька из настоящего сценария, не переносить эти константы в приложение. Форма кошелька по умолчанию создаёт новый учёт с 14.09.2026; образцы редактирования и Operations показывают ранее созданные кошельки.

Восемь исходных операций служат образцами типов и ограничений. «Загрузить ещё» раскрывает локальный массив, не реализует API-курсор. Создание/изменение/удаление меняют только память этой страницы; балансы Wallets не пересчитываются. Нельзя использовать суммы разных страниц как сквозной финансовый расчёт. Ошибка сохранения переключается в секции проверки перед открытием формы. Ни запросов, ни постоянного хранения, ни изменения реальных финансовых данных нет.
