# Архитектурные решения (ADR)

Один ADR — одна часть логики или один модуль. Каждый ADR описывает **текущее** решение целиком: что решено, почему, что из этого ещё не попало в код («Состояние реализации») и какие варианты отклонены. История изменений решений не ведётся слоями внутри ADR — она в `git log` и в [docs/PROGRESS.md](../../PROGRESS.md).

| ADR | Тема |
|---|---|
| [0001](./0001-modular-monolith.md) | Модульный монолит: границы модулей, способы связи, транзакция на команду, доменные события, фоновые задачи |
| [0002](./0002-record-lifecycle.md) | Жизненный цикл записей: удаление, архивирование, мягкое удаление операций, история кошелька, использование справочников |
| [0003](./0003-balance-history.md) | История баланса: слепки, каскадный пересчёт, плановая задача, досоздание пропусков, заявленный баланс |
| [0004](./0004-currencies-and-exchange-rates.md) | Валюты и курсы: Frankfurter v2, доступные и активные валюты, обновление, смена основного кошелька, исторические курсы |
| [0005](./0005-money-precision.md) | Денежные суммы: произвольная точность, строки в API |
| [0006](./0006-audit.md) | Аудит: захват изменений, актор, метки времени, объём журнала |
| [0007](./0007-repository-structure.md) | Структура репозитория и конвенции размещения файлов |
| [0008](./0008-deployment.md) | Деплой: Railway и Vercel, одно окружение |
| [0009](./0009-frontend-visual-architecture.md) | Визуальная архитектура фронтенда: UI kit v0.3 |

Новое решение попадает в ADR своей темы. Новый ADR заводится только для темы, которой в таблице нет.
