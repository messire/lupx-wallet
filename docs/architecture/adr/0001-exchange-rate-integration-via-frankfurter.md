# ADR-0001: Интеграция курсов валют через сервис Frankfurter

## Статус

Принято

## Контекст

Бизнес-требования (раздел 2 [wallet_business_prompt_ru_v2.md](../../requirements/wallet_business_prompt_ru_v2.md)) описывают только общие правила работы с курсами валют: загрузка из общедоступного бесплатного сервиса, автообновление, ручное обновление с перезапуском таймера, использование последнего успешного курса при ошибке. Конкретный сервис и модель получения курсов между произвольными парами валют в тексте не названы — это было зафиксировано как открытые вопросы Q5 и Q6 в [user-scenarios.md](../../requirements/user-scenarios.md).

Приложение хранит кошельки в разных валютах. Общая сумма и историческая общая сумма всегда выражаются в валюте текущего основного кошелька (см. термины **Primary Currency**, **Total Amount** в [glossary.md](../../requirements/glossary.md)). Основной кошелек может меняться пользователем в любой момент, соответственно валюта, относительно которой нужно знать курсы всех остальных кошельков, тоже может меняться.

## Решение

1. **Источник курсов** — сервис [Frankfurter](https://www.frankfurter.app/) (бесплатный, общедоступный, без ключа/регистрации).
2. **Периодичность автообновления** — раз в сутки. Это осознанное изменение исходного текста требований (там было указано «раз в три часа»); изменение внесено пользователем явно при ответе на Q5 и зафиксировано как отклонение от исходного документа в [user-scenarios.md](../../requirements/user-scenarios.md#изменения-исходных-требований).
3. **Ручное обновление** — по кнопке, вне очереди; после успешного или неуспешного ручного обновления суточный таймер автообновления запускается заново от момента ручного обновления.
4. **Модель получения кросс-курсов** — курсы запрашиваются напрямую как пара «валюта кошелька → текущая основная валюта» (Frankfurter поддерживает произвольную базовую валюту в запросе `base`). Промежуточная фиксированная базовая валюта не используется.
5. **Реакция на смену основного кошелька** — при смене основного кошелька (и, следовательно, основной валюты отображения) курсы для всех валют кошельков перезапрашиваются заново с новой базовой валютой.
6. **Отказоустойчивость** — если запрос к Frankfurter завершился ошибкой (в автообновлении или при ручном обновлении), используется последний успешно загруженный курс для соответствующей пары; дата/время последнего успешного обновления не изменяются.

## Последствия

- Приложение зависит от доступности внешнего сервиса Frankfurter; при длительной недоступности сервиса курсы «замораживаются» на последнем известном значении (это поведение прямо предписано бизнес-требованиями, не является побочным эффектом).
- Смена основного кошелька инициирует дополнительный сетевой запрос курсов (а не пересчет из уже загруженных данных), что упрощает модель данных (не нужно хранить и поддерживать полную матрицу кросс-курсов), но добавляет сетевую зависимость в сценарий, который раньше считался чисто локальным (переключение основного кошелька).
- Если у пользователя в кошельках есть валюта, которую Frankfurter не поддерживает, автообновление для этой валюты будет систематически завершаться ошибкой. Обработка такого случая (уведомление пользователя, деградация функциональности для этой валюты) не описана бизнес-требованиями и должна быть спроектирована отдельно при реализации.
- Точность курсов используется такая, какую возвращает Frankfurter, без дополнительного округления (соответствует разделу 2 исходных требований).

## Альтернативы

- **Фиксированная базовая валюта с расчетом кросс-курсов на стороне приложения** (например, всегда хранить курсы к EUR/USD и вычислять A→B как A→база→B). Отклонено пользователем при ответе на Q6 в пользу прямого запроса пары к Frankfurter — предпочтение отдано более простой модели данных без промежуточной валюты.
- **Другой источник курсов** (ECB напрямую, платные API и т.п.) — не рассматривался, пользователь явно назвал Frankfurter.
